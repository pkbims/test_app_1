# Style sample sources

The full-resolution originals here (1024×1024 PNG, gpt-image-2, not from any user's
room — PRD U4) are the masters behind the compressed versions actually shipped in
`../Resources/Assets.xcassets/<style-id>.imageset/`. Kept here, outside `Resources/`,
so they're **not** picked up by the app target's resource bundling (that path is
recursive over `Resources/` in `project.yml`) — the app only ships the compressed
copies.

Originally 6 styles (`warm-minimal`, `scandi`, `mid-century`, `japandi`,
`modern-coastal`, `industrial`); grew to 18 in `Style.swift` per
`prompt_review/HANDOFF.md` §2, then to the full 62 for DecorAI name parity
(backend `prompt.py` commit 6959d92).

**All 62 are standalone concept images, not app renders.** Every one — the
original 18 included — is a direct `gpt-image-2` text-to-image call built from
that style's own name/summary/guide text in `backend/app/render/prompt.py`. There
is no base photo, no `render_id`, no database row, no architecture-preservation
constraint: nothing routes through `POST /v1/rooms/{id}/renders` or any worker
job. This is a deliberate choice, confirmed against the original 18's own git
history — a plain styled-room prompt reads as a stronger, more distinctive
showcase image than a real restyle of one fixed sample photo ever does, because
it isn't constrained to keep that photo's specific layout, furniture, and
architecture recognizable.

The 44 new ids briefly shipped a *different* version, generated by mistake
through the real render pipeline (one sample photo, `walls: "repaint"`,
`furniture: "add"`, `decor: "plenty"`) — technically a real restyle, but visibly
the same room's layout redecorated 44 times, not 44 distinct concept images. That
version was reviewed and rejected in favour of this one, which matches the
original 18's actual process instead.

`gpt-image-2` is rate-limited by OpenAI to 5 requests/minute org-wide — generate
sequentially, not in parallel, if scripting a batch of these.

Regenerate the shipped copies (e.g. to change size/quality) with:

```bash
sips -Z 450 -s format jpeg -s formatOptions 78 <style-id>.png \
  --out ../../Resources/Assets.xcassets/<style-id>.imageset/<style-id>.jpg
```

`450px` because the card displays at 118×150 points (150pt tall ≈ 450px at 3x) — no
reason to ship more resolution than the largest size it's ever shown at. `78`
quality JPEG cut each file from ~1.6–2MB to well under 100KB with no visible
artifacting at card size; re-check that visually if you change either number.
